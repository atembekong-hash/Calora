Planner Reconstruction Directive — Product Excellence Extension

Continue the current Planner reconstruction and edit implementation.

Do not discard or restart the work already completed.

Instead, expand the scope from "implementing missing planner features" to "building the strongest meal-planning experience in any nutrition application."

The implementation should remain fully compatible with everything already built.

Shift in objective

Do not think of this as finishing an edit mode.

Think of this as designing the operating system for meal planning.

Every interaction should reduce cognitive load.

Every interaction should preserve context.

Every interaction should make planning feel calm, intelligent, and effortless.

The Planner should feel alive without becoming distracting.

It should never feel like a static CRUD interface.

It should never feel like a collection of unrelated cards.

It should feel like one continuous planning experience.

---

Design philosophy

Nothing should exist because it looks impressive.

Everything should exist because it reduces work.

The Planner should remove decisions instead of creating more.

The interface should remain calm.

Minimal.

Focused.

Highly legible.

Professional.

No clutter.

No unnecessary controls.

No visual noise.

No decorative animation.


---

Living interactions

The Planner should feel alive through behavior rather than decoration.

Examples include:

Meals smoothly moving into place.

Context preserved after edits.

Selected days transitioning naturally.

Shopping automatically reflecting planning changes.

Nutrition summaries updating instantly.

Cards acknowledging completed edits.

Subtle state transitions.

Adaptive shortcuts.

Useful empty states.

Context-aware recommendations.

Every motion should explain a state change.

Never animate simply because something changed.


---

Planning continuity

Planning should feel like one continuous workflow.

Nothing should feel disconnected.

Planner

↓

Shopping

↓

Diary

↓

Every transition should preserve as much context as possible.

The user should never feel like they entered a different application.


---

Empty-state philosophy

An empty meal slot should never communicate failure.

It should communicate possibility.

Instead of saying nothing exists,

it should intelligently offer:

saved meals

favorite meals

recipes

recent meals

custom meals

AI suggestions

meal templates

meal duplication

appropriate recommendations based on existing habits


---

Planner intelligence

The Planner should gradually become more useful without taking control.

Examples:

Frequently planned breakfasts become easier to reuse.

Frequently paired meals become suggestions.

Repeated weekly patterns become templates.

Common grocery combinations become reusable.

Frequently adjusted serving sizes become defaults.

Frequently swapped meals become quick replacements.

Everything remains user-controlled.

Nothing happens automatically without consent.


---

Editing philosophy

Editing should feel direct.

Not administrative.

Users should never wonder:

Can I edit this?

Where do I edit this?

How do I replace this?

How do I undo this?

How do I save this?

The interface should answer those questions visually before the user asks them.

Question every layout.
