Perform a COMPLETE PROJECT-WIDE IMAGE AUDIT for Calora.

MISSION

Scan the entire application, frontend, backend, APIs, seed/mock data, database integrations, image utilities, assets, recipe systems, restaurant systems, planner systems, logging flows, and every user-facing screen.

The objective is to determine exactly:

1. Everywhere images are currently used.
2. Everywhere images should reasonably be used but currently are not.
3. Every place where an image does not accurately represent the meal, food, restaurant item, recipe, ingredient, feature, or role attached to it.
4. Every image that is reused for multiple unrelated foods/items.
5. Every generic/fallback/placeholder image currently being presented as though it represents a specific food.
6. Every case where different meals or menu items incorrectly resolve to the same image.
7. Every item that has no reliable image source.
8. Where each image originates: local asset, hardcoded URL, API, database, fallback mapping, generated data, seed data, cache, or other source.

CORE IMAGE RULE

For food, meal, recipe, and restaurant content:

THE IMAGE MUST MATCH THE ITEM IT REPRESENTS.

A photo displayed for:
"McChicken"
must visually represent a McChicken or an appropriately verified equivalent.

A photo displayed for:
"World Famous Fries - Small"
must represent fries.

A photo displayed for:
"Whopper"
must represent a Whopper or verified Whopper image.

A photo displayed for:
"Black Beans"
must represent black beans.

Do not use a generic salad/bowl/meal photograph simply because a correct image is unavailable.

The same generic image must not silently represent multiple unrelated foods.

IMAGE UNIQUENESS

Treat image identity as part of the content identity.

Each distinct recipe, prepared meal, restaurant menu item, or other food entity should have an image specifically associated with that entity whenever a suitable image is available.

Different serving sizes or variants may intentionally share an image ONLY when they are genuinely the same food product and the image remains accurate. Example: Small, Medium, and Large McDonald's fries may legitimately use the same verified fries image.

Do not flag legitimate variant reuse as an error.

However:
McChicken ≠ McDouble
Whopper ≠ Cheeseburger
Chicken Nuggets ≠ Chicken Sandwich
Cheese ≠ Black Beans
Chicken ≠ Rice
and unrelated items must not share generic food imagery.

RESTAURANT AUDIT

Pay special attention to restaurant data.

The current UI visibly contains suspicious repeated generic images across unrelated menu items.

Determine:

- Why these duplicates occur.
- Whether the upstream API supplies real item-specific images.
- Whether Calora is discarding valid image URLs.
- Whether fallback logic is overriding images.
- Whether restaurant data has been hardcoded or seeded.
- Whether images are mapped by category instead of actual food identity.
- Whether the database schema supports item-level image identity.
- Whether caching causes incorrect images.
- Whether there are licensing or API restrictions affecting image availability.
