# Calora App-Wide Responsiveness & Interaction Remediation Plan

**Scope:** synthesis of the supplied independent audit results only. No new source research, native build, production-data mutation, or security/authentication bypass was performed for this plan.

**Objective:** remove confirmed functional, recoverability, accessibility, and responsive-layout defects while preserving the repairs already evidenced in Reports 214 and 220. This is an implementation plan, not evidence that the listed repairs have been made.

## 1. Decision rules and delivery order

| Priority | Meaning | Release treatment |
|---|---|---|
| **P0** | Confirmed broken route contract, misleading durable-save outcome, or stale/incorrect content that can block a core user task. | Repair and add focused automated regression coverage before acceptance. |
| **P1** | Confirmed accessibility, recovery, interaction, or state-feedback defect with a material user impact. | Complete in the same remediation release unless explicitly waived with an accessible alternative. |
| **P2** | Confirmed consistency/layout hardening issue, or a source-level issue whose visual severity must be measured at runtime. | Implement after P0/P1 foundations; do not close without the listed device matrix. |
| **Verify only** | A risk or behavior not established as a new defect by the audits. | Test; do not characterize as a regression until reproduced. |

### Recommended implementation sequence

1. **Create shared primitives first.** Establish one tab/safe-area metric, accessible modal/chrome semantics, target-size helper, async feedback semantics, and an external-link launcher. This prevents per-screen compensating constants from reappearing.
2. **Remove P0 state-contract breaks.** Repair route-driven Voice permission startup, Planner durable-persistence reporting, Coach transcript replacement, and recoverable content states.
3. **Apply P1 screen fixes using the shared primitives.** Include retry states, input labels, busy/selected state, live feedback, and navigation/timer ownership.
4. **Harden responsive layouts and input ownership.** Address fixed/absolute geometry, keyboard-owned scrolling, long text, large type, narrow screens, and nested gesture arbitration.
5. **Run focused tests, then authorized runtime verification.** Unit/source-contract tests cannot substitute for the device/accessibility matrix below. No native build is required for the focused test work; provider-dependent checks must use an approved QA account/fixture only.

## 8. Acceptance gates

1. **P0 closure:** Voice route works from undetermined permission through denial/grant; Planner never represents failed durability as success; Coach never exposes prior conversation as selected conversation; all have deferred-promise/race tests.
2. **Shared-contract closure:** all shared Back/backdrop/notice/target/spacing changes land before dependent screen migrations; role/state/label and one-handle tests pass.
3. **P1 closure:** each confirmed recoverability and accessibility finding in Section 2 has a test naming its failure mode and a user-visible recovery/announcement path.
4. **Responsive closure:** no primary surface closes until 320dp Android, a small iPhone/home-indicator device, Android 3-button and gesture navigation, large font, keyboard-open input, and web zoom/keyboard checks are recorded.
5. **Provider closure:** where authorized external/provider testing is unavailable, record the exact blocked dependency and retain fail-closed behavior; do not mark the journey verified from source inspection alone.
6. **Safety constraints:** no production data changes, no account/entitlement/security bypass, and no native build are part of this plan. Use mocks, test doubles, and approved QA accounts/fixtures for integration evidence.
