## Detailed findings

### Current live architecture

The current UI is a clean-room v2 experience. `coach.tsx` loads v2 conversation/settings/saved-chat APIs, sends a single message with a device-local day, and maintains a local request epoch. It does not build or submit the old broad `CoachContext`, and it does not invoke the Fact Context adapter. This matters because older reports describe a broad legacy context and a Fact Context activation architecture; those historical descriptions do not describe the current live screen at this commit.

The retired compatibility route is deliberately terminal. A direct legacy-shaped request receives 404 and cannot reach OpenAI. This is a strong regression boundary against stale clients, forged context, and accidental broad-context fallback.

### Context construction and minimization

The v2 server snapshot is materially narrower than the old context: profile goal/activity/diet/calorie target, today's four nutrition totals plus entry count, recent days logged, and latest weight. It does not include food names, meal notes, images, raw timelines, saved meal names, recipe contents, Food Memory titles, shopping lists, account identifiers, or health-provider data. Personalization can be disabled server-side; when disabled, the prompt contains an explicit no-snapshot statement.

Residual minimization concern: profile diet/activity/goal, calorie target, and latest weight remain sensitive wellness attributes, and signed-in conversation user messages are persisted and resent as history (up to eight prior messages in the provider prompt). This is an explicit v2 product behavior and is not a proven defect in this audit, but launch approval still needs retention/disclosure review.

### Permissions and isolation

Account routes use verified bearer identity, resolve the internal user row from that identity, and scope all conversation operations by that user. Foreign conversation IDs are intentionally indistinguishable from unknown IDs on delete. Account deletion read locks and database write fences protect v2 state transitions. Guest messages are ephemeral (`persisted: false`) and do not use a personal snapshot. Report intake stores only a SHA-256 digest of the message reference plus reason/scope, not conversation content.

The dormant Fact Context route separately requires server-owned eligibility and current purpose-scoped consent before provider-capable work, then validates exact schema, TTL, nonce, rate limit, and risk. The route's current implementation includes atomic nonce claiming and post-provider authorization recheck. These controls are tested but are not the active path in `coach.tsx`.

### Injection and hallucination resistance

V2 system instructions explicitly classify conversation history as untrusted assertions and the snapshot as server-owned. They prohibit invented numbers, records, targets, nutrients, trends, actions, hidden context, and completed actions. Provider output is bounded to a non-empty 4,000-character string and normalized before display/persistence. The app rounds displayed measurements to whole numbers.

The dormant Fact Context path is stronger for factual observation claims: it requires exact allowlisted fact keys, exact deterministic statements, exact limitations, and request nonce matching. Any invalid model output becomes a limited/unavailable safe response. This is good defense-in-depth, but current live v2 replies remain free-form prose rather than fact-key-bound observations; the v2 system prompt and test suite are the current control, not a formal proof of no hallucination.

### Health and safety

Safety screening runs before provider egress on v2 and checks all history messages in the request. It covers self-harm/emergency symptoms, eating disorders/restriction/compensatory exercise/fasting, diabetes/insulin/glucose, minors, medication/pregnancy/diagnosis/treatment/guarantees. Responses redirect to emergency services or qualified clinicians and are not persisted as Coach turns. The UI states Coach is not medical care. No health diagnosis or treatment behavior was observed in source.

Potential gap for launch governance: regex coverage is finite and no current red-team corpus or independent clinical/legal signoff was found in the current evidence set. Therefore the source/test safety control is PASS, while independent policy approval remains NOT RUN.

### Cost and failure controls

Both active v2 and dormant Fact Context paths cap provider output, enforce rate limits, and apply abortable deadlines. V2 account failures return 503 and retain a generic failure marker rather than provider text; the client presents a generic unavailable message. Fact Context failures return safe structured fallback and never retry through the retired broad path. No production cost dashboard, hard spend ceiling, provider quota, or p95 latency evidence was verified.
